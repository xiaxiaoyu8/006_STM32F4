# 现象
STM32通过**四线**ST-Link连接PC,keil魔术棒里找不到芯片ID,CubeProg显示connectfail,需要under reset下载,
两种原因:

# 可能的两种原因
1.进入了待机模式:
(
    ## ✅ 你可以现在这样操作一下：

1. 拔掉 USB，只保留 ST-LINK 供电。
2. BOOT0 = 0，BOOT1 = 0。
3. 确认 SWCLK → PA14，SWDIO → PA13，GND 共地，3.3V 正确。
4. 打开 CubeProgrammer，设置 “Connect under reset”。(STM32 ST-LINK Utility也可以,先按住开发版上RESET按钮,点击连接,接着全芯片擦除)
5. 按住复位键 → 点击 “Connect” → 松开复位。

👉 如果此时能连上，立刻点“Erase & Programming”把旧程序擦掉。)

至此,芯片ID可正确显示在keil里


2.芯片被上了二级锁(level 2)
这种情况无解


## ✅ 1. **检查 BOOT 引脚设置是否正确**

你说目前是：

* **BOOT0 = 1**
* **BOOT1 = 0**

👉 这个组合代表 MCU 会从 **系统存储器（System Memory）启动**，进入 **ISP 模式（比如 UART Bootloader）**。
⚠️ 这种模式下，如果你用的是 **ST-LINK（SWD调试）**，很可能 **连接失败**。

👉 如果你是想用 **ST-LINK 下载程序（SWD）**：

* 把 **BOOT0 = 0**
* 把 **BOOT1 = 0**

👉 如果你想用 **串口下载**，才需要 BOOT0 = 1。
目前你的引脚设置和调试方式冲突了。
✅ 建议：先把 BOOT0 改回 0 再试一次连接。

---

## ✅ 2. **检查 SWD 接线是否正确**

ST-LINK V2 与 STM32F103C8T6 的常用接线如下👇

| ST-LINK V2 | STM32F103C8T6 |
| ---------- | ------------- |
| SWCLK      | PA14          |
| SWDIO      | PA13          |
| GND        | GND           |
| 3.3V       | 3.3V          |
| NRST(可选)   | NRST(复位脚)     |

⚠️ 很多新手会把 SWCLK 和 SWDIO 反接，导致连接不上。
✅ 请你对照这个表确认接线是否无误。

> ✅ **注意**：ST-LINK 的 3.3V 输出必须和板子共地，电压也要匹配（不能用5V直接上电）。

---

## ✅ 3. **给板子上电**

你的板子通过 USB 上电了，看灯亮是有供电，但注意：

* ST-LINK 自身 3.3V 电流有限，如果 USB 板子也接电了，注意不要两个电源相互冲突。
* 建议先只用一个电源源（比如只用 ST-LINK 供电），排除干扰。

---

## ✅ 4. **检查是否有程序锁定芯片**

如果之前你的 MCU ：

* 上过保护（RDP Level 1 或 2）
* 或者程序把 SWD 接口禁用了（比如用了 PA13、PA14 做 IO）

👉 ST-LINK 也会无法连接。

✅ 解决方法：

* **按住板子复位键**，然后在 CubeProgrammer 上点击“Connect”。
* 如果有短暂的“连接成功”，立刻执行 **“Full chip erase”**。
* 如果没有 NRST 线，可以用跳线手动短接 NRST → GND 再放开。

---

## ✅ 5. **CubeProgrammer 连接设置**

打开 `STM32CubeProgrammer` → 右上角选择接口：

* 选择 `ST-LINK`
* 速度设为 **低速（比如 100kHz）**
* 关闭“Reset Mode: Software Reset”，改成“Connect under reset” 试试。

---

## ✅ 6. **确认 ST-LINK 驱动**

在电脑“设备管理器”中查看：

* ST-LINK 是否正常识别
* 没有黄叹号
  👉 如果不正常，请重新安装 ST-LINK 驱动（ST 官网）。

---

## 🧰 补充排查技巧

* 如果 STM32F103C8T6 烧了错误程序，SWD口会被占用，**复位+上电连接**是比较常用的救砖手段。
* 如果连 **NRST** 也不行，那可能芯片进入了 RDP Level 2 → 这意味着彻底锁死，无法再擦写或读取。
